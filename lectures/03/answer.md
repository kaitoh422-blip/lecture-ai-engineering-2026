# 第3回 解答

## 宿題

- 取り組んだレベル：基礎


- やったこと：agent.py の INSTRUCTIONS と、tools.py のツールのdocstringを書き換え、同じ質問を --trace 付きで実行した。指示やツール説明の違いによって、呼び出されるツール、引数、最終回答がどのように変化するかを比較した。
使用した質問：第3回で扱うLoRAについて簡潔に教えてください。
この質問には、具体的な用語である「LoRA」と、講義回を表す「第3回」の両方が含まれている。そのため、用語検索と講義概要取得の使い分けを確認できると考えた。


- 結果：
同じ質問「第3回で扱うLoRAについて簡潔に教えてください。」を、変更前後で --trace 付きで実行した。

変更前は、用語集を検索する search_glossary のみが呼び出され、LoRAが第2回で扱われる技術であることが回答された。一方、第3回の講義内容を取得する get_lecture_summary は呼び出されなかった。

INSTRUCTIONS の変更後は、search_glossary と get_lecture_summary の両方が呼び出された。その結果、LoRAは第2回で扱う内容であり、第3回ではAIエージェントを扱うことが説明された。また、回答に内部のツール名が表示されなくなった。

さらに、get_lecture_summary のdocstringに使用条件と引数の説明を追加した。変更後も2つのツールが正しい引数で呼び出され、LoRAの説明と第2回、第3回の違いを含む、より詳しい回答が得られた。


- 考察：
今回の実験から、INSTRUCTIONS を具体的にすると、モデルが使用するツールと最終回答に含まれる情報が変化することが分かった。特に、変更前は1つだけだったツール呼び出しが、変更後は2つになり、質問に含まれる用語と講義回の両方を確認できた。

また、docstringはモデルにツールの用途や引数を伝える説明として使われる。使用条件、使用しない条件、引数の意味を具体的に記述することで、モデルがツールを選択しやすくなると考えられる。

一方、ツール呼び出しが増えたことで、入力トークンは1,113から1,807へ、出力トークンは156から336へ増えた。表示されたコストも0.0007239から0.0013821へ増加した。回答は詳しくなったが、処理量とコストも増えるため、必要なツールだけを使うように指示することが重要だと分かった。



- 取り組んだレベル：実装

- やったこと：
学習内容をMarkdown形式で learning_log/ フォルダに保存する save_learning_log ツールを作成した。ツールには、学習テーマを受け取る topic と、記録内容を受け取る content の2つの引数を設定した。
また、ファイル保存は取り消しにくい操作であるため、ツール登録時に requires_approval=True を指定した。ツールが呼び出された際には、保存予定のテーマと内容を表示し、利用者が y または N を入力して承認または拒否できる処理を追加した。
（詳細なコードはagent.pyとask.py参照。）

- 結果：
利用者が学習内容の保存を依頼すると、save_learning_log が呼び出され、ファイルを作成する前に承認画面が表示された。
承認画面で y を入力した場合は保存処理が実行され、learning_log/ フォルダにMarkdownファイルが作成された。--trace でも、ツールの呼び出しと保存結果を確認できた。
一方、N を入力した場合は保存処理が中止された。拒否テスト前後のファイル数はいずれも2件であり、新しいファイルが作成されていないことを確認できた。

- 考察：
requires_approval=True を指定することで、ファイル作成のような取り消しにくい操作を、利用者が内容を確認した後に実行できた。
また、拒否した場合はツールの保存処理が実行されず、ファイルも増加しなかった。この仕組みにより、エージェントが誤って保存ツールを選択した場合でも、利用者が実行前に内容を確認して中止できる。そのため、承認機能はエージェントによる重要な操作の安全性を高めるために有効だと考えられる。

- 取り組んだレベル：発展

- やったこと：
演習で作成したPydantic AI版と同じ INSTRUCTIONS とツールを使い、エージェントを組み立てる部分だけをGoogle ADKで書き直した。

adk_agent/glossary_agent/ フォルダを作成し、__init__.py と agent.py を追加した。ADK版では、Agent の instruction に既存の INSTRUCTIONS を渡し、tools に次の3つの関数を登録した。
search_glossary
get_lecture_summary
make_quiz

その後、次のコマンドでADK版を起動した。
PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent

Pydantic AI版との比較には、基礎課題と同じ質問を使用した。
「第3回で扱うLoRAについて簡潔に教えてください。」


- 結果：
ADK版では、LoRAが第2回で扱うPEFT手法であり、事前学習済みの重みを固定して、低ランク行列の小さなパラメータだけを学習する技術であると説明された。

さらに、第3回のテーマはAIエージェントであり、Pydantic AIを使ったツール呼び出しや、エージェントループの仕組みを扱うことが説明された。回答の最後には、関係する回として第2回と第3回が示された。

Pydantic AI版でも同様に、LoRAは第2回、第3回はAIエージェントの内容であると回答された。そのため、同じ指示とツールを渡せば、異なるフレームワークでも回答の主要な内容はほぼ同じになることを確認できた。


- 考察：
Pydantic AIでは引数名が instructions であるのに対し、ADKでは instruction だった。また、ADKではCLIが読み込むエージェントを root_agent という名前で定義した。

Pydantic AIとGoogle ADKでは、エージェントやツールを登録するコードの書き方が異なっていた。Pydantic AIでは作成したエージェントに対してツールを後から登録するのに対し、ADKではエージェントの作成時にツールのリストをまとめて渡すため、ADK版の方がエージェントの構成を一か所で確認しやすかった。

一方、同じ INSTRUCTIONS とツールを使用したことで、両方の回答内容はほぼ同じになった。どちらも質問中の「LoRA」と「第3回」を別々に確認し、LoRAは第2回、第3回はAIエージェントの内容であると説明した。

回答の文章量や表現には違いがあり、ADK版はPydantic AI版より簡潔だった。ただし、生成AIの回答には実行ごとの揺れがあるため、この違いがすべてフレームワークによるものとは断定できない。今回の比較から、フレームワークの違いは主にエージェントの組み立て方に現れ、同じ指示とツールを与えれば、回答の主要な内容は共通することが分かった。
